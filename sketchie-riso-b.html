01 / How it runs

Copy in. Video out.
Plates kept.

Set the copy

Write a prompt or hand over a document. Document mode follows your source instead of inventing a generic script. Prompt, PDF, Word, PowerPoint, TXT and Markdown all go in.

Draw it

Sketchie writes the script, then draws each element stroke by stroke, timed to the word of narration it belongs to. Nothing lands on the board that the narration never mentions.

Keep the graph

You get the MP4 in 16:9, 9:16 or 1:1, and the scene graph behind it. The file is the deliverable. The graph is why the second version is cheap.

02 / The scene model

Fix one scene. Not the whole video.

Every scene is addressable. Edit its fields, or describe the change in a sentence. Only that scene re-renders.

Illustration using an explainer about DNS. Pick a scene.

Plain language edit

"In scene 02, name the resolver and show the request leaving the laptop first."

Set a field directly, such as the heading, the narration or a label. Or describe a larger change in one sentence.

Version 1

Correct, but the viewer cannot tell who is asking.

Version 2

The laptop sends first, the resolver is named, the answer returns on its own line.

Scenes 01, 03 and 04 were not re-rendered

Addressable

Every scene has an identity in the scene graph, so an edit can name the one it means.

Versioned

Each edit creates a version. Earlier ones stay available, and you can revert.

Contained

Re-rendering one scene leaves the rest of the video exactly as it was.

04 / The spec

Rules, not vibes.

Sketchie publishes the research behind its generator, graded by evidence. These are constraints the output satisfies, not promises about what a video does to a viewer.

12 to 30sScene length

One idea per scene, long enough to land and short enough to hold.

3 to 7Elements per scene

Counted at the end of the scene, heading included.

2 to 5sReveal spacing

A new element on that rhythm, never two closer than 1.2 seconds.

500msWord sync

Each element appears within that window of the word it belongs to.

140 to 160Words per minute

Spoken register, contractions allowed, read at a human pace.

3 wordsLabel limit

A keyword, never a sentence echoing the narration.

Question

Every video closes by asking the viewer to produce the answer.

Pause

The video holds, so the answer is theirs before it is given.

Recap

Then one line closes the loop. The question is never replaced by a summary.

The six minute ceiling comes from engagement research across 6.9 million online learning sessions, and is a deliberate cap rather than a technical limit. Longer material becomes a chaptered series. Read the full spec with citations.

06 / Questions

The honest FAQ.

Can I edit a single scene?

Yes. Scenes are addressable, so an edit targets one of them, that scene re-renders on its own, every edit creates a version, and you can revert to an earlier one.

What if the source is too long?

Longer material becomes a chaptered series rather than one long video. Individual videos are set in 30 second increments up to six minutes, or Sketchie picks the length.

How does a video end?

With a retrieval beat: a question, a pause, then a one line recap. The pause is deliberate, because producing the answer yourself is the part the research supports.

Can I try the editor without paying?

Yes. Two watermarked videos, up to one minute each, no card required, and the editor is included rather than held back for paid plans.

Is Sketchie faster than Simi?

No, and Sketchie says so. Simi is faster at first generation. The argument is about the time it takes to reach a video you will actually publish, revisions included.

Can developers drive it?

Yes. An API that returns the video with its scene graph, an MCP server so agents can generate and edit, and a CLI. API access starts on Plus.
